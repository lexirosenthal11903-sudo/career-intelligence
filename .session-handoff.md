### What to build (two behaviours, ONE slice — grill both first)
1. **Proactive check-in on return.** Root cause already found: on return with stored history,
   `src/hooks/useArloChat.ts` (~L99–121) loads the transcript, drops a "New session" divider, and **never
   calls `initiate()`** — so the advisor sits silent on open threads. (Real case: Lexi asked about a visa
   days ago; the conversation IS persisted in the `conversations` table and reloaded, so the advisor had it
   in front of it and still never followed up. So this is **passivity, not a memory gap.**) The advisor
   should speak first on return and pick up the unresolved thread ("you were weighing the visa — where did
   that land?"). Needs a notion of *open/unresolved* threads, not just durable facts.
2. **Hold the thread — focused time, gently.** A real mentor doesn't just follow every topic-switch. If the
   user is mid-task (e.g. a CV) and jumps elsewhere, the advisor guides them to use the time well ("happy to
   come to that — finish the CV first, or park it and switch?"). NOT rigid: an anxious switch can be the real
   need; read the dial.

### Grill questions to resolve before building
- When does the advisor proactively re-open vs stay quiet? (Every return? Only with an open thread? Gap-aware?)
- What counts as an "open/unresolved thread" — and how is it stored? (New field? Inferred from the transcript
  the model already gets? A `remember`-style note?) Avoid a to-do-app feel (deferred elsewhere).
- Hold-the-thread: how does it know what the user is "mid-task" on, and how hard does it push (it must never
  feel controlling for an anxious user)? When does following the switch win?
- No-gamification + no-pressure guardrails: check-ins are care/awareness, never a chase (ADVISOR_PERSONA §4).

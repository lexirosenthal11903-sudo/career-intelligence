## ▶ WHAT SESSION 46 SHIPPED (3 code + 3 doc commits, all on staging, all green)
Two fixes, both closing drift classes. Each: tsc 0 · lint 0 · unit + e2e · £0 (no paid eval — no chat-prompt change).

- **Cold error on a SUCCESSFUL tool action → warm ack (`51b77cf`).** Root cause: a tool commits mid-turn, then the
  model's final turn ends with no usable text; the route returned that empty content as a clean 200 and the
  client's `join("") || ERROR_MSG` painted the cold error next to the "✓" success echo. Fix: `src/lib/chat-reply.ts`
  `ackForSilentCommit` speaks a warm "Done, I've got that for you." ONLY when the model went silent AND an action
  committed this turn; real replies + genuinely-empty (nothing committed) turns untouched. Wired into the
  non-tool-use return in `src/app/api/chat/route.ts`. Reproduced first: `tests/chat-reply.test.mjs` (6 unit tests
  modelling the exact client reduction).
- **Stale-cache drift on per-user API reads (`fcc2b6b`).** The "flaky" `state-sync.spec.ts:50` was a REAL bug: GET
  `/api/profile` (and siblings) had no `Cache-Control`, so the browser's heuristic cache could serve a stale copy of
  the user's private data — the exact "advisor says done, screen shows the old thing" drift, plus a private-data
  cache leak. Fix: `src/lib/api-response.ts` `jsonNoStore` applied to every authed per-user GET (profile, results,
  applications, documents, matched-jobs, save-job, recap). Per-route helper chosen over a middleware header so each
  route keeps its own auth semantics (e.g. `/api/documents` returns `{documents:[]}` for unauthed, not 401).
  Previously-intermittent suite now 4/4 green on repeat runs.

56 unit tests (was 50). Both findings closed in `FEATURE-ROADMAP.md` "Session 45/46 findings".
